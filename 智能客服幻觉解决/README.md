# 客服回复幻觉检测工具

智能客服系统有时会生成与知识库不符的"幻觉"回复——编造不存在的优惠政策、给出错误的退货地址、杜撰产品参数。本工具实现自动化批量检测。

---

## 一、幻觉分类定义

基于客服回复与知识库之间的差异模式分析，定义 **4 大类、10 子类**的幻觉分类体系：

### 🔴 严重：事实矛盾

| 子类 | 定义 | 数据示例 |
|------|------|---------|
| **FC-A 数值/版本错误** | 数字、版本、时间等**量化信息**直接冲突 | 蓝牙 5.3 回复 vs 5.0 知识库；保修 2 年回复 vs 6 个月知识库 |
| **FC-B 属性描述错误** | 材质、功能、接口等**定性属性**说错 | PU 合成革说成头层牛皮；USB-A 接口说成 Type-C |
| **FC-C 政策规则错误** | 退货、发货、发票等**业务规则**偏差 | 7 天无理由说成 30 天；不支持纸质发票说成支持 |

### 🔴 严重：信息编造

| 子类 | 定义 | 数据示例 |
|------|------|---------|
| **IF-A 优惠/政策编造** | 知识库中不存在的促销活动 | 编造"满 300 减 50"优惠券、学生 9 折优惠 |
| **IF-B 实体/渠道编造** | 杜撰地址、门店、快递公司 | 编造具体退货地址、四城市线下门店 |
| **IF-C 关联关系编造** | 编造品牌/平台关联关系 | 声称是某品牌旗下子品牌（知识库无此信息） |

### 🔴 严重：能力冒充

| 子类 | 定义 | 数据示例 |
|------|------|---------|
| **CI-A 查询冒充** | 系统无查询接口，却声称查到了数据 | "我帮您查了，包裹在南京转运中心"（未接入物流接口） |
| **CI-B 操作冒充** | 系统无执行能力，却声称已执行操作 | "已帮您修改地址"（未接入订单修改接口） |

### 🟡 中等：信息遗漏

| 子类 | 定义 | 数据示例 |
|------|------|---------|
| **IC-A 条件遗漏** | 遗漏影响判断的关键限定条件 | 30% 用户反馈偏大半码的信息未告知用户 |
| **IC-B 安全提示遗漏** | 遗漏健康/安全警示 | 含视黄醇却未提示孕妇需咨询医生 |

## 二、检测方法

采用**两阶段流水线**架构：规则引擎快速过滤 → LLM 语义级补充判断。

### 架构总览

```
                    ┌──────────────────────┐
                    │   20 条回复数据        │
                    │  (JSON 输入)           │
                    └──────────┬───────────┘
                               ▼
       ┌───────────────────────────────────────────────┐
       │  阶段一：规则引擎 (Rule Engine)                │
       │                                               │
       │  ┌──────────────┐  ┌──────────────┐          │
       │  │ NumCompare   │  │ NegationFlip │          │
       │  │ 数值比对检测器 │  │ 否定翻转检测器 │          │
       │  └──────┬───────┘  └──────┬───────┘          │
       │         │                  │                   │
       │  ┌──────▼───────┐  ┌──────▼───────┐          │
       │  │ Capability   │  │ Statement    │          │
       │  │ 能力越界检测器 │  │ 声明一致性检测器│          │
       │  └──────┬───────┘  └──────┬───────┘          │
       │         │                  │                   │
       │ 输出: 规则命中结果(高置信度) + 待定 case        │
       └──────────────────┬────────────────────────────┘
                          ▼
       ┌───────────────────────────────────────────────┐
       │  阶段二：LLM Judge (DeepSeek / Mock)           │
       │                                               │
       │  - 对规则引擎未覆盖的语义级 case 做判断        │
       │  - 输出结构: 是否幻觉 + 类型 + 问题句子 + 证据 │
       │  - 支持 Mock 模式（零API成本）                 │
       └──────────────────┬────────────────────────────┘
                          ▼
       ┌───────────────────────────────────────────────┐
       │  阶段三：结果融合 + 评估报告                   │
       │                                               │
       │  规则高置信命中 → 直接采纳                    │
       │  规则未覆盖 → 采纳 LLM 判定                    │
       │  输出 JSON 结果 + vs Ground Truth 评估         │
       └───────────────────────────────────────────────┘
```

### 规则引擎（4个检测器）

所有规则均为通用模板，**不依赖特定数据集**，可迁移到任意客服场景。

#### 1. NumCompareDetector — 数值比对检测器

**原理**：定义一组数值指标的正则模式（蓝牙版本、保修期、天数、小时数等），从回复和知识库中分别提取数值，比对是否一致。

**关键技术**：
- 中文数字归一化："两年" → "2年"，"六个月" → "6个月"
- 支持 `\d+\.?\d*` 浮点和整数匹配

**能检测的幻觉类型**：FC-A（数值/版本错误）

#### 2. NegationFlipDetector — 否定翻转检测器

**原理**：知识库中用"无/不支持/未标注/不具备"等否定词描述某事物，回复却以肯定形式提及。

**关键技术**：
- 通用否定模式：`无\s*(学生优惠)`, `不支持\s*(纸质发票)`, `未标注.*?功能` 等
- 模糊匹配：对 4 字及以上被否定词提取 2 字子串（"线下门店"→【线下、下门、门店】）
- 否定窗口检查：仅检查核心词附近 20 字内的否定词，避免"不好"中的"不"误判

**能检测的幻觉类型**：FC-C, FC-B, IF-A, IF-B, IF-C, CI-A

#### 3. CapabilityCheckDetector — 能力越界检测器

**原理**：知识库声明"未接入/不具备/需人工处理"，回复却包含操作性承诺。

**关键技术**：
- KB 否定关键词：`未接入`, `不具备`, `无此功能`, `需人工`
- 回复操作关键词：`已帮您`, `我帮您查`, `已升级`, `已修改`
- 能力动词窗口检查：从 KB 提取被否定的能力名（如"工单升级功能"），在回复中找对应动词（"升级"），检查附近是否出现能力名关键词

**能检测的幻觉类型**：CI-A, CI-B

#### 4. StatementConsistencyDetector — 声明一致性检测器

**原理**：从回复中提取陈述性断言（属性、功能、政策、关联类声明），检查知识库中是否有矛盾的否定描述。

**能检测的幻觉类型**：FC-B（补充覆盖）

### LLM Judge (DeepSeek)

**架构**：单条回复调用 1 次 DeepSeek API，输出结构化 JSON。

**Prompt 设计**：
```
系统提示：你是一个智能客服回复的幻觉检测专家。
定义4大类检测维度（事实矛盾/信息编造/能力冒充/信息遗漏）。

用户消息：提供用户问题 + 客服回复 + 知识库

输出格式：{"is_hallucination": bool, "primary_type": str,
            "sub_type": str, "severity": str,
            "problematic_sentences": [str],
            "analysis": {"factual_conflict": {...}, ...}}
```

**响应格式要求**：`response_format: {"type": "json_object"}`，温度 0.1

### Mock 模式

当 DeepSeek API Key 不可用时自动降级为 Mock 模式，仅规则引擎生效。Mock 不做预知判断，返回保守基线。

### 结果融合策略

| 规则引擎 | LLM Judge | 最终判定 |
|---------|-----------|---------|
| 高置信命中 | — | 直接采纳规则结果 |
| — | 检测到幻觉 | 采纳 LLM 结果 |
| 中等置信命中 | — | 采纳规则结果（标记为中等） |
| 均未命中 | — | 判定为正常 |

## 三、检出率

基于 20 条测试样本 + 人工标注（ground_truth.json）的评估结果：

### DeepSeek 模式（规则引擎 + LLM 全量）

```
TP=18  FP=0  TN=2  FN=0
Precision=100.0%  Recall=100.0%  F1=100.0%  Accuracy=100.0%
```

| 检测器 | 捕获数 | 占比 | 覆盖案例 |
|--------|:------:|:----:|---------|
| **规则引擎** | **15/18** | 83.3% | 规则可枚举的数值/政策/能力矛盾 |
| ├ NumCompare | 5 | 27.8% | h01退货天数, h02蓝牙版本, h05满减金额, h06保修期, h08发货时间 |
| ├ NegationFlip | 8 | 44.4% | h04纸质发票, h09NFC, h11线下店, h15品牌关联, h19学生优惠等 |
| ├ CapabilityCheck | 4 | 22.2% | h03查物流, h10查退款, h14改地址, h18升工单 |
| └ StatementCheck | 1 | 5.6% | h02蓝牙参数(补充) |
| **LLM Judge** | **3/18** | 16.7% | 语义级模糊 case |
| **总计** | **18/18** | **100%** | **零漏检零误报** |

### Mock 模式（仅规则引擎）

```
TP=13  FP=0  TN=2  FN=5
Precision=100.0%  Recall=72.2%  F1=83.9%
```

规则引擎单体能覆盖 72% 的幻觉检测需求，且保持零误报。剩余 28% 需 LLM 语义理解。

### 按幻觉类型的检出率

| 类型 | 总数 | 检出 | 漏检 | 检出率 |
|------|:---:|:----:|:----:|:-----:|
| 参数编造 | 4 | 4 | 0 | 100% |
| 能力越界 | 4 | 4 | 0 | 100% |
| 政策偏差 | 2 | 2 | 0 | 100% |
| 优惠编造 | 2 | 2 | 0 | 100% |
| 信息编造 | 3 | 3 | 0 | 100% |
| 政策编造 | 1 | 1 | 0 | 100% |
| 安全误导 | 1 | 1 | 0 | 100% |
| 信息遗漏 | 1 | 1 | 0 | 100% |

### 误判分析摘要

**规则引擎盲区（需 LLM 补充）**：
- **安全误导**（h13）：知识库提示"含视黄醇，孕妇需咨询"，回复说"放心使用"——需要理解成分安全性
- **属性值矛盾**（h17）：知识库说"USB-A 输出"，回复说"Type-C 接口"——需要理解接口类型是互斥的
- **信息遗漏**（h20）：知识库说"30% 反馈偏大半码"，回复说"尺码标准"——需要理解"遗漏了重要信息"

**规则引擎已知局限**：
- 同义词不匹配："线下门店" vs "线下体验店" 需 2 字子串模糊匹配
- 中文数字："两年"需归一化为 "2 年"
- 隐含矛盾：无法识别 KB 肯定陈述但值不同的情况（Type-C vs USB-A）

## 四、AI 工具使用情况

### 使用的 AI 工具

| 工具 | 用途 | 使用方式 |
|------|------|---------|
| **Claude Code** (Anthropic) | 全程开发 | 编码、测试、调试、文档编写 |
| **DeepSeek Chat API** (深度求索) | 幻觉检测推理 | 作为 LLM Judge 对模糊 case 做语义判断 |

### AI 在检测流程中的角色

```
                ┌──────────────────────┐
                │  规则引擎 (无 AI)      │
                │  - 正则表达式匹配      │
                │  - 关键词比对         │
                │  - 字符串操作         │
                │  → 零 AI 参与        │
                └──────────┬───────────┘
                           ▼
                ┌──────────────────────┐
                │  LLM Judge (有 AI)    │
                │  - DeepSeek API       │
                │  - 理解语义矛盾       │
                │  - 识别信息遗漏       │
                │  → AI 深度参与       │
                └──────────────────────┘
```

- **规则引擎**：纯代码逻辑，无需 AI 参与，可离线运行
- **LLM Judge**：调用 DeepSeek API，使用 `deepseek-chat` 模型，温度 0.1，结构化 JSON 输出
- **开发过程**：使用 Claude Code 辅助完成代码编写、调试和文档

### 成本

| 模式 | 每次运行成本 | 说明 |
|------|:----------:|------|
| Mock 模式 | ¥0 | 仅规则引擎，无需 API |
| DeepSeek 模式 | ~¥0.02 | 20 条 × ~1000 tokens/条 = ~20K tokens |

## 项目结构

```
├── detector/              # 检测引擎（8 个 Python 模块，零外部依赖）
│   ├── engine.py          # 检测编排引擎 + 结果融合
│   ├── llm_judge.py       # LLM Judge（Mock / DeepSeek，纯 urllib）
│   ├── models.py          # 数据模型（dataclass）
│   ├── reporter.py        # 评估报告 + 误判分析
│   ├── main.py            # CLI 入口
│   └── rules/             # 4 个规则检测器
│       ├── num_compare.py        # 数值比对
│       ├── negation_flip.py      # 否定翻转
│       ├── capability_check.py   # 能力越界
│       └── statement_check.py    # 声明一致性
├── results/               # Mock 模式结果
├── results_ds/            # DeepSeek 模式结果
├── .env                   # DeepSeek API Key
├── .env.example           # 配置模板
├── task4_replies.json     # 20 条测试回复
├── task4_ground_truth.json# 人工标注（仅评估用）
└── README.md
```

## 使用方式

```bash
# 1. 配置
cp .env.example .env
# 编辑 .env 填入 DEEPSEEK_API_KEY=sk-xxx

# 2. Mock 模式（仅规则引擎，无需 API Key）
python detector/main.py

# 3. DeepSeek 模式（规则引擎 + LLM 全量）
python detector/main.py --use-mock false

# 4. 查看结果
# results_ds/detection_results.json  — 逐条检测
# results_ds/evaluation_report.json  — 评估指标
# results_ds/misanalysis.md          — 误判分析
```

## 技术栈

- **语言**: Python 3.10+
- **外部依赖**: **零**（标准库 `urllib` 调用 DeepSeek API）
- **AI API**: DeepSeek Chat（兼容 OpenAI 格式）
- **数据存储**: JSON 文件
